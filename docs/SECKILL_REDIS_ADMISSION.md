# Redis 秒杀入口与异步订单（2026-11-20）

正常抢券请求不访问 MySQL。此前逐请求核验、跨请求 SQL 合批及核验专用连接池已经移除；历史 158→21 ms、548→475 ms 是旧方案的对照数据，不作为本版本性能结果。

## 数据流

```text
发布活动事务提交 / 启动 / 后台发现新活动
    → 读取 MySQL 活动时间、初始库存、历史购买资格
    → Redis 原子发布 ready 状态

HTTP 抢券 → Redis 登录与限流 → Redis 订单编号
    → Lua：就绪状态、购买资格、重复预留、活动时间、在途上限、库存
    → Redis 预留库存和原订单编号、UNKNOWN 回执
    → RocketMQ Broker 确认 → ACCEPTED / 排队中
    → 消费者 MySQL 本地事务：库存条件扣减、唯一约束、订单与关单 Outbox
    → 提交后更新购买资格与完成回执
```

Broker 确认不等于订单已经创建。HTTP 仍等待 Broker 确认，订单在消费端异步创建。发送不确定时保留原编号及库存预留，走原有重试、核对和补偿；入口没有新增 SQL Outbox。订单详情、券包、支付、取消、消费者及后台恢复仍允许查数据库。

## 预热与状态

`SeckillActivityCache` 在活动发布事务提交后准备 Redis；应用就绪时扫描一次，之后默认每 60 秒扫描。按活动编号分页发现未结束活动，购买历史按订单编号每页 500 条加载。

| Redis 数据 | 用途 |
| --- | --- |
| `seckill:activity:{voucher}` | `ready`、活动起止时间、初始化标记、预热令牌及租约 |
| `seckill:stock:{voucher}` | 可预留库存；已有值不被重启、扫描覆盖 |
| `seckill:purchased:{voucher}` | 用户 → 已创建订单编号；包含取消订单，`__ready__` 表示历史已准备 |
| `seckill:order:{voucher}` | 仍占用库存的临时预留/购买记录，供按订单释放 |
| `seckill:request-user:{voucher}` | 用户 → 当前预留订单编号，防止旧补偿释放新预留 |

准备过程先关闭未就绪活动，通过 30 秒租约及随机令牌竞争发布权；令牌或租约失效不能发布。历史购买资格采用追加方式加载，不清空并发完成的购买记录，最后由 Lua 原子设置历史就绪与活动就绪标记。活动时间来自 MySQL `UNIX_TIMESTAMP`，入口用 Redis `TIME` 判断，避免多实例 JVM 时间与时区差异。

新活动只有在没有历史订单、待处理预留、资格集合及原请求映射的条件下才能初始化库存。已有库存始终保留。已初始化活动丢失库存，或数据库存在历史订单但 Redis 库存缺失时，保持不可受理并记录日志，禁止直接拿 MySQL 库存覆盖可能尚未消费的预留。

缓存未准备完整时返回业务失败 `秒杀活动暂未就绪，请稍后重试`；活动时间不符、库存不足各自返回原业务错误；在途上限触发 429。所有分支都不从抢券接口回源。后台查询失败由下一轮重试。

## 一人一券与取消

保持原数据库 `(user_id,voucher_id)` 唯一约束对应的业务规则：创建过订单即不能再次购买，取消后仍返回原订单编号。入口只返回已提交提示，详细支付、取消等状态通过订单查询接口获取，不在重复抢券请求中查询数据库。

消费者提交后，在同一 Redis 脚本中写入永久购买映射、更新回执并移除在途索引。回执过期不影响购买资格。若处理的是重复消息，映射保存实际已存在的订单编号。

取消通过数据库状态条件更新竞争，订单取消与 SQL 库存恢复在同一事务；提交后调用专用 Lua，核对预留所属订单，移除库存占用并最多回补一次，保留永久购买资格。取消回补没有提前暴露到数据库事务提交之前。后台每轮最多扫描 100 条已取消订单，按订单编号循环重试漏掉的释放，因此进程退出或 Redis 短暂失败后仍可补做。创建明确失败的补偿与取消释放分开，晚到的失败补偿不能释放已提交购买的库存。

## 部署与恢复

- SQL 连接池恢复为单池、默认总上限 10；移除 `eligibility-batch` 配置、读取线程和独立核验池。MQ 发送批次与在途上限保留。
- 发布本版本前停止旧实例，再统一升级。旧实例不检查新活动就绪标记，不能混合运行。
- 交易状态应使用持久化 Redis、`noeviction` 和合理内存预算，活动期间不要给库存及资格状态配置普通缓存 TTL。它们参与受理状态管理。
- Redis 全量丢失而 MySQL 已有历史订单时，需暂停入口、核对并排空 MQ 和未知请求，在维护窗口重建库存及资格。后台预热不会猜测库存，也不会在每个请求中尝试恢复。
- Docker 的 Redis 初始化脚本只初始化演示 GEO，不再硬编码秒杀库存为 100。库存由活动预热建立。
