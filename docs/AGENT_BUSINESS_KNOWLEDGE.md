# LocalPerks 业务知识与服务边界

本说明依据当前 Java Controller、VoucherOrderServiceImpl、秒杀 Lua 与消息处理代码整理。规则文档用于解释业务，当前价格、库存和个人订单状态必须调用实时接口。

## 秒杀购买与使用规则

秒杀通过 Redis Lua 预扣库存、RocketMQ 异步消息和 MySQL 订单处理。提交成功只代表请求已接收，不能保证最终成单。重复抢同一张券可能返回原订单，应继续查询原订单状态。

优惠券 beginTime/endTime 是购买活动的开始和结束时间，不代表到店核销有效期。券的实际使用日期、适用人数、预约要求、门槛和叠加限制应依据商家明确的券规则。接口只写“以店铺说明为准”时，无法确认今晚一定可用，需要联系商家。没有明确叠加规则时，不计算多张叠加优惠。

## 订单状态与异步查询

展示状态码：10排队中、11处理中、12待支付、13已支付/已获得券、14已取消、15失败、16已核销、17退款中、18已退款。排队或处理中需要继续轮询，不能误报为成功。失败原因未由接口提供时，不能推断为某个确定性系统故障。

## 取消订单与超时

只允许当前登录用户取消自己的未支付订单。Java 使用状态条件更新避免与支付竞争，并复用原有库存回补逻辑。已支付订单不能当作取消未支付订单处理；重复取消已经取消的订单返回其当前状态。系统还通过原有延迟消息处理未支付超时取消。

## 支付与售后

当前项目只有开发模拟支付接口，没有真实支付通道、支付回调或真实扣款。Agent 模拟支付默认禁用。真实退款、售后受理和核销 API 尚未实现；文档中的退款状态用于显示历史数据，不代表用户可以直接发起退款。不能承诺已退款或已扣款。

## 推荐指标与消费估算

店铺 avgPrice 是人均参考值，不是菜单报价或实际消费总额。单张券的券面节省等于面值减券售价，前提是足额使用面值。估算实付等于 max(人均参考价×人数－面值,0)＋券售价；估算人均为估算实付除人数。这些估算不能承诺实际结账金额，不允许擅自叠加多张券。

## 店铺服务说明

当前店铺 API 提供名称、分类、地址、经纬度、人均参考和营业时间等字段。座位数量、两人套餐、预约余量、包间、停车和实时等位情况没有对应可靠字段。推荐时可以按已提供字段筛选，但不能承诺未提供的服务设施或接待能力。

## 登录、确认与隐私

查询个人券包、订单状态和交易操作必须先登录，由 Java 验证当前用户及订单归属，模型不能指定他人的用户 ID。下单、取消和开发模拟支付需本人核对操作摘要并显式确认，使用幂等键避免重复提交。网络超时不能当作确定失败，应该查询核对，不应盲目重试写操作。
