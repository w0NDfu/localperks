# Agent 共享调度与用户偏好

2026-11-15。默认对话配置仍为 `gpt-6-luna`，Embedding 为 `text-embedding-3-small`（1536维），Rerank 为 `BAAI/bge-reranker-v2-m3`。名称来自实际配置，兼容接口背后的底层模型无法由本项目独立鉴定。

## 已实现的链路

`Java身份验证 → PostgreSQL任务/幂等记录/共享队列同事务提交 → 多实例领取 → 同会话FIFO → 再鉴权 → 工作流 → 持久事件 → 通知/查询`

- 登录异步入口为 `POST /agent/tasks`。队列按数据库分配的受理序号排序；后续同会话任务不能越过未完成的前一任务，其他会话可以并行。
- 领取使用短事务、`FOR UPDATE SKIP LOCKED` 和全局容量判断；执行模型期间不占用数据库连接。任务和队列分别持有执行者租约，过期执行者不能回写接管者结果。
- 默认每实例16路、集群256路、队列10000条、每用户32条。队列满明确拒绝，排队超过300秒进入可恢复状态；过期清理分批执行，避免长事务。
- 同步/SSE/显式恢复兼容接口使用 PostgreSQL 会话执行权和实例门控；跨实例FIFO保证适用于持久异步入口，不把兼容入口描述为共享队列消费者。
- 同步兼容请求和持久队列使用独立的本地执行预算，避免已领取任务在工作流超时之外等待；两者均经过共享模型配额。本人恢复任务完成后会释放原共享队列位置，短暂会话冲突重新排队，不把后续问题误标成失败。

## 身份转交与恢复

登录令牌以标准 Fernet 认证加密后保存到专用 Redis 键，默认900秒，PostgreSQL只保存随机引用，不保存令牌或密文。任务体与事件不记录凭据。接管者解密后重新调用 Java `/user/me`，校验身份仍与任务所属用户一致。

所有实例必须共享 `AGENT_CREDENTIAL_KEY`，从安全配置管理器或忽略文件加载。首次升级运行 `python -m api.bootstrap`，仅为已有 `.env.platform` 补齐新键，不覆盖数据库和模型凭据。不要提交该键。密钥丢失、Redis凭据过期或登录失效时进入 `waiting_auth`，用户重新登录并重交原编号即可恢复，禁止绕过鉴权执行。

实例正常退出会将未完成任务交回队列；进程崩溃依赖租约到期后接管。任务已经完成但队列尚未来得及确认时，接管者读取终态并结束队列记录，不重复调用模型。交易操作仍必须经过独立本人确认和业务幂等。

## 模型配额与通知

每实例复用模型 HTTP 连接池。Redis Lua 按共同命名空间、状态schema、接口地址和模型，原子限制60秒滑动窗口 RPM、TPM 和在途调用。输入按UTF-8字节及协议开销保守预留，输出设置 Token 上限；成功且返回用量时结算，失败或缺失用量保留预留，不能填零。Redis不可用时禁止直接绕过配额调用模型。

`AGENT_MODEL_RPM/TPM/CONCURRENCY` 是应用预算，默认6000/6000000/128，不代表已获得供应商相同额度；实际部署应按账户配额统一配置。副本配置不一致时拒绝配额申请，避免不同副本各算一份。未验证供应商侧2000路真实推理。

每实例一个 PostgreSQL LISTEN 连接接收任务ID通知，WebSocket在事件变化时查询持久事件，15秒补查用于监听重连和通知丢失后的恢复，不再让每条连接每0.5秒查库。通知不携带登录令牌、问题或回答。

## 用户偏好

前端助手页“我的偏好”支持读取、保存、清除；后端按认证用户隔离，版本条件更新避免旧页面覆盖新设置。删除清空偏好内容并保留递增版本，防止旧页面将已删除偏好写回。

优先级为本轮明确要求、会话已有条件、用户确认的长期默认。预算、距离、分类排除进入程序筛选；分类匹配为排序加分，不能越过预算或优惠资格。缺少足够分类数据时保留不确定性，不声称已满足分类排除。风格通过请求上下文传入模型，不使用共享可变历史；不自动从浏览和聊天推断并持久化偏好。

分类/店名匹配无法验证菜品、忌口或过敏原，界面及回答保留说明。当前不训练用户专属模型，也不将私人对话导入公共知识库。

## 验证口径

`tests/persistence/run.py` 创建独立 PostgreSQL/Redis，禁止真实模型和业务HTTP；常规回归覆盖幂等、调度、租约、跨用户访问、偏好版本与删除、条件优先级、筛选排序及并发风格隔离。额外设置 `AGENT_TEST_CLUSTER_LOAD=1` 可运行2000独立用户、两个应用实例、全局模型并发6的测试替身负载；它验证调度与数据绑定，不是供应商并发性能或真实TCP吞吐测试。

首个工作副本负载在无限创建Redis连接时出现建连超时，已保留失败并改用有界阻塞连接池。修复后的阶段性测试为156通过、1跳过：2000任务全部完成、2000次模型替身调用，模型并发峰值6，受理P95约9948ms，总耗时约48.85秒。阶段结果（本地运行生成，不随源码上传）

受理耗时包含2000同时提交、鉴权替身、加密凭据与数据库操作，不包含真实入口网络。前端受理等待上限相应设置为20秒；结果不明时仍保留原请求编号。隔离存储使用tmpfs，验证数据库事务与进程恢复，不代表主机掉电验收。短期测试不能替代长期稳定性和生产容量验证。
